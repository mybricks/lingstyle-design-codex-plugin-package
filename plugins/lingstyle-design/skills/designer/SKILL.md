# Lingstyle 设计器

## 打开应用

用户要求打开 Lingstyle 应用、面板、设计器或插件 UI 时，直接调用 `lingstyle-design` MCP 服务的 `lingstyle_app_open`，无需确认。该工具加载 Lingstyle 应用，提供项目首页和设计器页面；设计器文件接口是否就绪以文件工具返回结果为准。

用户在对话中发送或引用本插件（包括仅发送插件、不附带文字）且当前没有打开 Lingstyle 应用时，默认意图是打开应用，主动调用 `lingstyle_app_open`，无需等待用户补充“打开”指令或再次确认。已有目标应用实例时直接使用，不要重复打开。用户明确说明其他意图时遵循其要求。

当前上下文中有`projectId`时直接操作应用已正常打开，不要重复调用 `lingstyle_app_open` 来打开应用。不要用浏览器打开 localhost 或启动开发服务器来代替插件应用。

## 开发设计器内的项目代码

创建或修改代码前，必须阅读 [面板代码开发规范](references/coding-standards.md)，遵循其中已填写的规则。规范适用于设计器虚拟项目中的代码。

1. 从当前面板上下文获取 `projectId`，每次文件工具调用都显式传入该值。缺少目标标识时请求用户打开目标设计器或提供当前面板上下文，不要猜测标识或选择其他面板。
2. MCP 工具调用除报错或返回 isError: true 外，都说明工具正常执行。

提供的 MCP 工具直接操作已打开设计器的虚拟文件系统。不要用终端或本地文件工具修改插件仓库来代替设计器内的项目操作。

## 选区与修改范围

用户附带 focus 选区或元素上下文时，根据其中的源码位置、结构和样式信息定位代码，默认仅修改该元素及完成需求所必需的相关代码。无法定位时说明缺少的信息，不要扩大为整个页面重建。没有选区时按用户需求确定范围。

## 错误处理

工具不可用、面板断开或设计器文件接口尚未就绪时，报告实际原因并停止依赖该接口的操作。写入或删除超时可能已经执行，先读取确认，再决定是否重试，不要盲目重复提交。
